## Repository layout

```
sdlc-agentic-ai-platform/
├── backend/          # Python SDLC agents, orchestrator, scripts, platform tests
│   ├── agents/       # Strands specialist agents + pipeline/ handoff JSONs
│   │   ├── _shared/  # Shared utilities (env, artifact store, pipeline runner, schemas)
│   │   └── <name>/   # One directory per agent
│   ├── scripts/      # run-sdlc-local.ps1, RDS apply, MCP helpers
│   ├── target-apps/  # FastAPI services built by developer-agent (git-ignored output)
│   ├── inputs/       # Plain-text requirement briefs
│   ├── tests/        # Platform pytest suite (not per-app tests)
│   ├── config/       # MCP catalog, AgentCore runtime config
│   ├── a2a/          # Agent-to-agent registry + agent cards
│   └── deploy/       # Bedrock AgentCore packaging
└── frontend/         # Next.js 14 (App Router) control-plane UI
    └── src/
        ├── app/      # Next.js routes — (app)/* pages + api/v1/* backend bridge
        ├── lib/      # api.ts (service layer), repo-reader.ts, artifact-store.ts
        ├── components/
        ├── features/
        ├── store/    # Zustand stores
        └── types/
```

## Backend setup

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Secrets go in `.env` at the **monorepo root** (or `backend/.env`). `.env.local` always wins (use it for RDS/Postgres overrides that should not land in `.env`). `_shared/env.py` merges both files with SSO-safe logic — never set static `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_SESSION_TOKEN` in files when `AWS_PROFILE` is configured.

```bash
cp .env.example .env   # fill in AWS_PROFILE, MODEL_ID, CODING_MODEL_ID, GITLAB_*, POSTGRES_MCP_*
aws sso login --profile eks-admin-user
```

## Run the pipeline

From `backend/`:

```powershell
.\scripts\run-sdlc-local.ps1 -Feature inventory-app -InputFile inputs\inventory-app.txt
```

Key skip/opt-in flags: `-SkipProduct`, `-SkipArchitect`, `-SkipDb`, `-SkipPostgres`, `-SkipDeveloper`, `-SkipGitlab`, `-SkipVerify`, `-WithQa`, `-WithJira -JiraProject <KEY>`, `-WithWebCrawler`.

Resume a partial run (e.g., DB + dev only):
```powershell
.\scripts\run-sdlc-local.ps1 -Feature inventory-app -InputFile inputs\inventory-app.txt -SkipProduct -SkipArchitect
```

Preset test levels (`run-pipeline-test.ps1`): `easy`, `medium`, `db`, `inventory`, `release-notes`.

## Run individual agents

```bash
# CLI
python agents/product-agent/product_agent.py --task "Checkout flow" --project PAY
python agents/architect-agent/architect_agent.py --context-file agents/pipeline/<app>.context.json
python agents/database-agent/database_agent.py --context-file agents/pipeline/<app>.context.json
python agents/developer-agent/developer_agent.py --target-app <app> --context-file agents/pipeline/<app>.context.json

# A2A server mode
python agents/product-agent/product_agent.py --serve-a2a   # listens on :9101

# RDS apply (standalone)
python scripts/apply_sql_to_rds.py --target-app <app>
```

## Tests

```bash
# Platform tests (from backend/)
python -m pytest tests/ -q

# Single test file
python -m pytest tests/test_pipeline_context.py -q

# Per-app tests (generated by developer-agent)
cd target-apps/<app>
python -m pytest tests/ -q
```

`tests/conftest.py` clears `POSTGRES_MCP_*` and `DATABASE_URL` before each test so live RDS credentials don't affect unit tests. Tests that require real RDS are in `scripts/postgres_mcp_smoke.py`, not the test suite.

## Frontend

```powershell
cd frontend
copy .env.example .env.local   # leave NEXT_PUBLIC_API_BASE_URL empty for local mode
npm install                     # or: yarn install
npm run dev                     # http://localhost:3000
```

`NEXT_PUBLIC_API_BASE_URL` unset → reads monorepo state via `/api/v1/*` routes (local). Set it to point at a deployed platform API.

## Architecture

### Pipeline flow

```
inputs/*.txt
  → product-agent   → docs/PRD/<app>.md + agents/pipeline/<app>.context.json
  → architect-agent → docs/design/<app>.md + diagram PNG
  → database-agent  → target-apps/<app>/db/sql/*.sql
  → apply_sql_to_rds.py (orchestrator step, skippable)
  → developer-agent → target-apps/<app>/ (FastAPI, tests, README)
  → local verify    → import smoke + pytest
  → gitlab-agent    → branch sdlc/<app> on GitLab
  → qa-agent        (opt-in: -WithQa)
```

### Transport modes

| Mode | When | Set via |
|------|------|---------|
| `local` (default) | Dev — orchestrator spawns each agent as a subprocess | `SDLC_PIPELINE_TRANSPORT=local` |
| `a2a` | AgentCore runtimes (cloud) | `SDLC_PIPELINE_TRANSPORT=a2a` + `AGENTCORE_A2A_PEER_URLS` |
| `auto` | Picks `a2a` when AgentCore/S3 env is set, else `local` | default |

### Artifact store

| Mode | Location | Set via |
|------|----------|---------|
| `local` (default) | `backend/target-apps/<slug>/` | `ARTIFACT_STORE=local` |
| `s3` | `s3://<bucket>/runs/<runId>/<slug>/` | `ARTIFACT_STORE=s3` + `ARTIFACT_S3_BUCKET` |

Path helpers in `_shared/pipeline_context.py` (e.g., `prd_rel_path_for_app`, `design_doc_rel_for_app`) switch automatically. `_shared/artifact_store.py` wraps S3/DynamoDB with local filesystem fallback.

### Strands agents pattern

Each agent in `backend/agents/<name>/<name>_agent.py` follows this pattern:
- `AGENT_NAME` constant + `<NAME>_SYS_PROMPT` system prompt string
- `Agent` from AWS Strands SDK backed by `BedrockModel` (Bedrock)
- MCP tools via `_shared/mcp_clients.py` or directly via `MCPClient`
- A2A server via `--serve-a2a` (port from `a2a/agent-registry.json`)
- Thin agents use `_shared/runner.py`'s `entrypoint()` — just pass `system_prompt` and `mcp_names`

### Key env vars

| Variable | Used by |
|----------|---------|
| `AWS_PROFILE` | All agents (SSO — preferred over static keys) |
| `AWS_REGION` | Bedrock model; default `us-east-2` |
| `MODEL_ID` | product/architect/gitlab agents |
| `CODING_MODEL_ID` | database/developer agents (code-heavy; typically Opus) |
| `BEDROCK_READ_TIMEOUT` | Streaming timeout (default 600s) |
| `ARTIFACT_STORE` | `local` or `s3` |
| `ARTIFACT_S3_BUCKET` | Required when `ARTIFACT_STORE=s3` |
| `ARTIFACT_DYNAMODB_TABLE` | Run index table (default `sdlc-pipeline-runs`) |
| `SDLC_PIPELINE_TRANSPORT` | `local`, `a2a`, or `auto` |
| `AGENTCORE_A2A_PEER_URLS` | JSON map of agent → AgentCore invoke URL |
| `GITLAB_PERSONAL_ACCESS_TOKEN` | gitlab-agent |
| `GITLAB_PROJECT_PATH` | gitlab-agent |
| `GITLAB_API_URL` | gitlab-agent (Juno: `https://code.junodev.net`) |
| `POSTGRES_MCP_*` | database-agent + apply_sql_to_rds.py |

### Frontend service layer

`frontend/src/lib/api.ts` is the single typed service layer — all pages read through it. In local mode it calls `/api/v1/*` Next.js routes; those routes read live monorepo state via `frontend/src/lib/repo-reader.ts` (filesystem) and `frontend/src/lib/artifact-store.ts` (S3 when configured). The frontend **never executes agents** — it only reads platform state.

MCP server entries are stored in `frontend/data/mcp.json` (git-ignored) via routes under `frontend/src/app/api/mcp/*`. Raw secret values are rejected — store them as `${env:NAME}` references (`frontend/src/lib/mcp-store.ts`).

### AgentCore (cloud) deployed agents

Deployed runtimes are tracked in `backend/config/agentcore/runtimes.json` (no secrets). The SDLC pipeline (`orchestrator → product → architect → database → developer → frontend → gitlab`) is deployed to `us-east-2` (`sdlcPipeline` key). `frontend-agent` is opt-in via `with_frontend` until the control plane defaults it on. `qa-agent`, `web-crawler-agent`, `devops-agent`, and `security-agent` are outside the default chain or not fully deployed. Deploy script: `backend/scripts/deploy-agentcore-agents.ps1`.

VPC-mode runtimes are parked — they need a NAT Gateway or VPC endpoints to reach ECR/S3/DynamoDB/Bedrock before they can be used.

## Adding a new agent

1. Create `backend/agents/<name>/<name>_agent.py` with `AGENT_NAME`, `<NAME>_SYS_PROMPT`, and either a custom `Agent` + tools or `entrypoint()` from `_shared/runner.py`.
2. Register port in `backend/a2a/agent-registry.json` and add an agent card under `backend/a2a/agent-cards/`.
3. Add a Cursor skill under `.cursor/skills/<name>/SKILL.md` if needed.

## Key conventions

- Python for Strands agents; TypeScript for the Next.js frontend. BullMQ TypeScript orchestrator is planned but not scaffolded.
- `_shared/schemas.py` defines `AgentMessage`, `TaskPayload`, `ResultPayload` for inter-agent envelopes.
- Target apps scaffold from `backend/target-apps/_template/`; each may have `.cursor/rules/` overrides.
- `_shared/validate_sql_artifacts.py` guards against nullable-column drift before RDS apply.
- `_shared/materialize_seed_passwords.py` replaces `__BCRYPT_PLACEHOLDER__` in seed SQL before apply.
- Pipeline handoff per run: `agents/pipeline/<feature>.context.json` (local) or `runs/<runId>/<slug>/context.json` (S3).
- Telemetry per agent run: `agents/pipeline/<feature>.<agent>-telemetry.json`; summarised by `_shared/pipeline_telemetry.py`.
