Hi Team,

We need an internal application that gives employees, managers, compliance teams, and administrators one central place to access company policies, operational procedures, regulatory guidance, and internal standards.

Today, these documents are stored across shared drives, email attachments, and different team folders. Employees often struggle to find the latest approved version, and compliance teams have limited visibility into which documents are being used, which policies are expiring, and whether employees have acknowledged important updates.

The application should use a Streamlit frontend with a FastAPI backend. It should also include a RAG-based assistant using Claude models for answer generation and Amazon Titan Embeddings for semantic search.

The goal is not only to store documents, but to make them searchable, traceable, version-controlled, and usable through a grounded AI assistant that always references the source material.

RAG workflow
An authorised user uploads a document through Streamlit
Streamlit sends the document and metadata to FastAPI
FastAPI validates the file and creates a document version record
The document is stored in persistent object storage
Text is extracted while preserving page and section information
Extracted text is cleaned and divided into configurable chunks
Amazon Titan Embeddings generates an embedding for every chunk
Chunks, embeddings, document metadata, version information, and source locations are stored in a vector-capable data store
Only approved and published document versions are available to normal employee searches
When a user asks a question:
The query is embedded
Relevant chunks are retrieved
Results are filtered based on the user’s permissions
The best chunks are provided to a Claude model
Claude generates a grounded answer with citations
The query, retrieved sources, response, latency, model, token usage, and feedback are recorded
Important business rules
Only approved and published document versions can be used for employee-facing RAG responses.
Draft, rejected, archived, or expired versions must not appear in normal employee search results.
Compliance users may access historical versions when authorised.
Users must never retrieve documents above their confidentiality level.
Department-restricted documents must be visible only to authorised departments.
Every AI answer must include at least one valid source citation.
The assistant must not invent an answer when the retrieved evidence is insufficient.
The assistant must clearly state when no reliable answer is available.
Retrieved content must be permission-filtered before it is sent to the Claude model.
A document cannot approve itself; the uploader and final approver must be different users.
A published document cannot be modified directly. A new version must be created.
Only one version of a document can be the currently published version.
Archiving a document must preserve all versions, acknowledgements, comments, and audit history.
Mandatory policy acknowledgements must be tied to a specific document version.
Acknowledgement of an older version does not count for a newly published version.
Duplicate document uploads should be detected using a file checksum.
Failed ingestion or embedding jobs must be retryable without generating duplicate chunks.
Reprocessing a document version must replace or update its existing vector records idempotently.
AI conversation history must not expose restricted source content after a user’s permissions change.
Soft deletion should be used for business records that require audit retention.

Success

The application is successful when:

A document owner can upload a policy, submit it for review, and have another authorised user approve and publish it.
The document is automatically extracted, chunked, embedded with Amazon Titan Embeddings, and indexed.
An employee can ask a question in Streamlit and receive a grounded Claude-generated answer with accurate citations.
Restricted or unpublished content is never exposed.
A mandatory policy can be assigned to employees and acknowledgement completion can be tracked.
Managers and compliance users can monitor overdue acknowledgements and expiring policies.
A new document version can be published without losing historical records.
Failed ingestion jobs can be retried safely without duplicate vector data.
The complete workflow operates through Streamlit and FastAPI with persisted data, auditability, and reliable error handling.
