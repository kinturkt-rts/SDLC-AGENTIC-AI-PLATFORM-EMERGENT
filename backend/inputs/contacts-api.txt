Build a small internal Contact Directory for our teams.

Problem:
- Colleague contact details live in spreadsheets and Slack threads and get out of date.
- People need a simple place to look up name, email, department, phone, and job title.
- Integrators should be able to add or update contacts safely; casual browsing should stay easy.

Who uses it:
- Anyone on the internal network can look up departments and contacts (read-only).
- Integrators with a shared API key can create, update, or deactivate contacts and manage departments.
- No employee login screens for v1 — just a shared key for write access. Health checks stay open for ops.

MVP features:
- Maintain departments (name and short code).
- Maintain contact cards: full name, email, department, optional phone and title, active/inactive.
- Browse and search contacts (by name or email), filter by department or active status.
- Soft-deactivate a contact instead of permanently deleting it in v1.
- Seed a few sample departments and contacts so demos work out of the box.

Business rules:
- Email addresses must be unique.
- Contacts must belong to a known department.
- You cannot remove a department that still has contacts tied to it.
- Writes without a valid API key should be rejected; reads stay open.

Must have for v1:
- Persisted data (not in-memory only).
- A simple API suitable for demos (Swagger is fine).
- No customer-facing web UI, chatbots, or SSO for this version.

Nice to have (later):
- Browser UI, personal logins, org chart, sync from HR systems.

Constraints:
- Internal use only.
- Keep secrets out of source code.

Success:
- Someone can list contacts, search by name, add a contact with the API key, and later deactivate them without losing the record.
- Looking up a department shows how many contacts it has.
