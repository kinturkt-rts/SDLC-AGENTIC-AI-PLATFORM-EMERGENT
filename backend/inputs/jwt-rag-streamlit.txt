Internal Policy RAG Portal — JWT auth + pgvector RAG + Streamlit UI (full pipeline test)

App idea (one paragraph):
HR and IT maintain internal policy PDFs (handbooks, security standards, expense policies) in
shared drives. Employees ask the same questions repeatedly in Slack. **Policy RAG Portal** lets
authorized staff log in with email/password, upload PDFs into named collections, and ask natural-
language questions in a Streamlit chat. Answers are grounded in retrieved chunks with citations
(document title, page, snippet). Low-confidence questions return an honest refusal — never
hallucinate. This brief intentionally exercises **JWT bearer auth end-to-end** (not API keys,
not X-Dev-User headers) so the product → architect → database → developer pipeline validates
login, role gates, bcrypt seeds, and Streamlit token flow.

Purpose:
- End-to-end SDLC chain: **product-agent → architect-agent → database-agent → developer-agent**
  (optionally qa-agent).
- Developer pattern: **B++** (Postgres + pgvector + Bedrock RAG) + **Pattern C**
  (`ui/streamlit_app.py` calling FastAPI over httpx).
- Validates **JWT authentication** in inputs, DDL seeds, pytest, Swagger, and Streamlit UI.
- Must run locally against shared RDS Postgres + Bedrock (same as other target-apps).

Current pain:
- Policy PDFs are scattered; keyword search fails on synonyms.
- No audit trail of who uploaded or queried what.
- Prior RAG demo (`rag-app-streamlit`) used dev headers — we need real login for showcase.

Personas & auth (JWT — required):
| Role | Login | Can do |
|------|-------|--------|
| anonymous | — | `GET /health` only |
| viewer | email + password (JWT) | Chat in collections they belong to; list/read documents; view own query history |
| contributor | email + password (JWT) | viewer + upload PDFs to assigned collections; create documents |
| admin | email + password (JWT) | Full access: create/archive collections, assign members, upload anywhere, read audit logs |

Auth implementation (MVP — must match training-compliance / inventory-app patterns):
- `POST /auth/token` body `{"email":"<email>","password":"<password>"}` →
  `{"access_token":"<jwt>","token_type":"bearer","role":"<role>","expires_in":<seconds>}`.
- Protected routes: `Authorization: Bearer <token>`; HS256 with `JWT_SECRET_KEY` from env.
- Passwords stored as bcrypt hashes in `users.hashed_password` — **never** plaintext in SQL.
- database-agent seed SQL: use real bcrypt hashes (or `__BCRYPT_PLACEHOLDER__` + `scripts/seed_dev_users.py`
  materialization — same guardrails as training-compliance).
- 401 missing/invalid/expired token; 403 insufficient role or collection scope.
- Streamlit: login form → store token in `st.session_state` → send Bearer on every httpx call.
- **Do not** use `X-API-Key`, `X-Dev-User`, or shared secrets for user identity in v1.

Stack (explicit — do not substitute):
- **Backend:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.x sync + psycopg, uvicorn,
  python-jose or PyJWT, passlib[bcrypt].
- **Database:** PostgreSQL on RDS; schema per feature slug; **pgvector** extension.
- **Vector column:** `embedding vector(1024)` — Titan v2 dimensions.
- **PDF bytes (MVP):** local disk `PDF_STORAGE_DIR` (e.g. `./var/pdfs`) — NOT S3 for MVP.
- **LLM (Amazon Bedrock):**
  - Answer: `us.anthropic.claude-sonnet-4-20250514-v1:0`
  - Embeddings: `amazon.titan-embed-text-v2:0` (1024 dim — must match vector column)
- **UI:** `ui/streamlit_app.py` + `ui/requirements.txt` (streamlit, httpx, python-dotenv); API port **8000**, UI port **8501**.
- **Parsing:** pypdf for text extraction.

Data model (database-agent owns `db/sql/`):
- `users` — id uuid PK, email text UNIQUE NOT NULL, hashed_password text NOT NULL,
  role enum (admin | contributor | viewer) NOT NULL, is_active bool DEFAULT true, created_at timestamptz
- `collections` — id uuid PK, name text NOT NULL, description text, owner_user_id FK→users,
  archived bool DEFAULT false, created_at timestamptz
- `collection_members` — collection_id FK, user_id FK, role enum (viewer | contributor | admin),
  UNIQUE(collection_id, user_id)
- `documents` — id uuid PK, collection_id FK, title text NOT NULL, file_path text NOT NULL,
  file_hash text, status enum (pending | processing | success | failed), uploaded_by FK→users,
  page_count int, created_at timestamptz, last_indexed_at timestamptz
- `document_chunks` — id uuid PK, document_id FK ON DELETE CASCADE, page_number int,
  chunk_index int, text text NOT NULL, embedding vector(1024), created_at timestamptz;
  HNSW or ivfflat index on embedding (cosine)
- `chat_sessions` — id uuid PK, user_id FK, collection_id FK, created_at timestamptz
- `chat_messages` — id uuid PK, session_id FK, role enum (user | assistant), content text,
  confidence float nullable, created_at timestamptz
- `query_audit` — id uuid PK, user_id FK, collection_id FK, question text, outcome enum
  (answered | refused | error), confidence float nullable, created_at timestamptz
- `audit_log` — id uuid PK, actor_user_id FK, action text, resource_type text, resource_id uuid,
  outcome text, created_at timestamptz

API contracts (FastAPI — implement all):
| Method | Path | Auth | Behavior |
| GET | /health | none | `{"status":"ok","checks":{"api":"ok","database":"ok"}}` |
| POST | /auth/token | none | OAuth2-style login; 401 bad credentials; inactive user → 401 |
| GET | /users/me | JWT | current user profile + role |
| POST | /collections | admin | create; 201 |
| GET | /collections | JWT | admin: all; others: collections where member |
| POST | /collections/{id}/members | admin | assign user + role; 409 if duplicate |
| GET | /collections/{id}/documents | JWT | member with viewer+; paginated list |
| POST | /collections/{id}/documents/upload | JWT | contributor+ on collection; multipart PDF + title;
  save bytes; ingest (chunk+embed); set status; audit log |
| GET | /documents/{doc_id} | JWT | member viewer+; metadata only |
| GET | /documents/{doc_id}/status | JWT | ingestion status |
| POST | /chat | JWT | body: `{collection_id, session_id?, question}`; member viewer+;
  embed question → pgvector top-k → confidence check → Claude answer + citations OR refusal |
| GET | /chat/sessions | JWT | own sessions for a collection |
| GET | /audit-logs | admin | filtered audit entries (upload, query, login failures optional) |

RAG pipeline (developer-agent — fully wired, NOT stubs):
1. Upload saves PDF under `PDF_STORAGE_DIR`, parses with pypdf, chunks (configurable size/overlap).
2. Each chunk embedded via Bedrock Titan v2; INSERT into `document_chunks`.
3. `/chat` embeds question, cosine top-k (default 5), `CONFIDENCE_THRESHOLD` (default 0.25 MVP).
4. If no chunks or score below threshold →
   `{"answer":"Not found in policy documents","confidence":0,"citations":[],"refused":true}`.
5. Otherwise Claude answers **only from retrieved chunks** with citations
   `[{document_id, title, page_number, snippet}]`.
6. Log outcome to `query_audit` and `audit_log`.

Business rules:
- Viewer cannot upload or create collections.
- Contributor cannot add collection members or read org-wide audit logs.
- Archived collections: read-only chat; no new uploads.
- Re-upload same file_hash in collection → 409 or idempotent skip (document in README).
- JWT `sub` = user id; dependencies resolve user + enforce collection membership.

Streamlit UI (required):
- **Login page** when no token: email + password → `POST /auth/token`; show 401 message on failure.
- **Sidebar:** logged-in email + role; logout clears session token.
- **Tabs (role-gated):**
  - **Chat** (viewer+): collection picker, message history, citations expander, confidence badge.
  - **Documents** (contributor+): upload PDF + title; list ingestion status.
  - **Collections** (admin): create collection, assign members.
  - **Audit** (admin): recent uploads and queries table.
- All API calls via httpx with `Authorization: Bearer {token}` — never duplicate RAG logic in Streamlit.
- Clear error when API unreachable.
