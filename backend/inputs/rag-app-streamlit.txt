Internal PDF Q&A — upload handbooks and ask questions with citations (Streamlit UI)

Problem:
Policy and handbook PDFs sit in shared drives. People search manually, guess at answers,
or ask colleagues who may not know the latest version. We want one internal place to upload
a set of documents, ask questions in plain English, and get answers grounded in those PDFs
with clear citations (which document, which page).

Who uses it:
- Contributors upload PDFs into a collection they manage.
- Viewers ask questions against collections they can access.
- Admins can review who uploaded what and who ran which queries.
- For MVP, simple dev-style sign-in is fine (no corporate SSO yet).

Features:
1. **Collections** — Group related PDFs (e.g. "HR policies", "Engineering handbook").
   Create a collection, give it a name and short description.
2. **Upload PDFs** — Add one or more PDFs to a collection. The system reads the file,
   breaks it into searchable pieces, and stores them so questions can find relevant text.
   Show each document's status: waiting, processing, ready, or failed.
3. **Chat / Q&A** — User picks one or more collections, asks a question, and gets an
   answer plus citations (document title, page, and a short snippet). If nothing in the
   uploaded docs supports an answer, say clearly **"Not found in documents"** — do not
   make things up.
4. **Document list** — See what's in a collection: titles, upload status, when it was last indexed.
5. **Audit trail** — Record uploads and queries (who, which collection, success or failure)
   so we can demo accountability internally.

Must have for v1:
- FastAPI backend with data stored in our existing Postgres database (including vector
  search for matching question text to document chunks — no separate search service for MVP).
- Amazon Bedrock for generating answers and for creating search embeddings from text.
- PDF files stored on local disk for MVP (not cloud object storage yet).
- **Streamlit UI** under `ui/streamlit_app.py` calling the API over HTTP — upload,
  document list, and chat pages. Streamlit must not duplicate business rules; it only
  talks to the API.
- Role-based access: viewers can read and ask; contributors can upload; admins see audit logs.
- README with local run steps (API + Streamlit), sample usage, and how to point at RDS.

Business rules:
- Answers must be based only on uploaded document content — never invent policy or facts.
- Low-confidence matches should return "Not found in documents" with no citations.
- Upload accepts PDF only; reject or clearly fail on unsupported formats.
- Users may only see collections and documents their role allows.

Constraints:
- Internal demo tool — keep secrets out of source code.
- Unit tests should pass without live AWS or RDS (mock the AI and storage layer).
- Must run locally against our RDS Postgres when configured with real credentials.

Success:
- Someone uploads a real PDF, asks a question in Streamlit, and gets a cited answer — or
  an honest "not found" if the docs don't cover it.
- pytest passes; API and Streamlit both start from the README instructions.
