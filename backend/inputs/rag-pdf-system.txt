We need an internal RAG system so teams can ask questions against our PDF documents and get answers grounded in the source files.

Current pain:
- Policy, runbook, and contract PDFs live in shared drives; people search manually or ask in chat and get guesses.
- No single place to upload a doc set, refresh it, and query with citations (page or section).
- We cannot tell if an answer came from a real document or was made up.

What we want:
- Upload PDFs (single files or batches), ingest them, and index them for semantic search.
- Chat or API where users ask natural-language questions and get answers with citations back to the PDF (page/snippet).
- Admin view to see which documents are indexed, last updated, and ingestion status (success/failed).
- Role-based access so only authorized users can upload, query, or manage collections.

Initial scope (MVP):
- PDF upload and storage with metadata (title, owner, upload date, collection/tag).
- Text extraction, chunking, embedding, and vector search (retrieve top chunks, then generate answer).
- Q&A interface with source citations in every response.
- Basic collection management (create collection, add/remove PDFs, re-index on update).
- Audit log of uploads, queries, and who accessed which collection.

Data and integrations:
- Object storage for raw PDFs and extracted text.
- Vector database for embeddings and similarity search.
- LLM for answer generation (prefer Amazon Bedrock; model choice TBD).
- Optional SSO for internal users.

Constraints:
- Documents may contain confidential or PII — access must be scoped per collection; no cross-tenant leakage.
- Answers must cite sources; if retrieval confidence is low, say "not found in documents" instead of hallucinating.
- Secrets via managed store only; TLS in transit and encryption at rest.
- MVP is internal use only; no public-facing portal.

Success expectation:
- Users get cited answers from indexed PDFs within a reasonable response time (target under 15 seconds for typical queries).
- Reduce time spent hunting through PDFs for policy or procedure questions.
- Clear ingestion status so admins know when a document is ready to query.
