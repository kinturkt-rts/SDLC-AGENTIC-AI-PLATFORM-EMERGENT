Audit Finding Tracker — audits, findings workflow, evidence, immutable audit trail

Client story:
Priya (Internal Audit) had 47 SOC findings in Excel that diverged from reality. Leadership needs
one system with evidence, comments, and an immutable trail of every status change.

MVP:
- Audits contain findings with severity, owner, due date.
- Workflow: open → in_remediation → pending_verification → closed (or send back).
- Evidence uploads + comment thread per finding.
- Executive read-only dashboards: overdue, by severity, by department.

Personas & auth:
| Role | Auth | Can do |
|------|------|--------|
| auditor | JWT | CRUD audits/findings; verify/close; all reads |
| assignee | JWT | Own findings: remediate, upload evidence, comment, request verification |
| executive | JWT | Read-only reports and finding detail (no downloads optional — allow read metadata) |
| anonymous | — | /health |

Data model (DDL under target-apps/audit-finding-tracker/db/sql/):
- users: id uuid PK, username, password_hash, role, full_name, department varchar(64), is_active
- audits: id uuid PK, name varchar(160), audit_type enum, period_start, period_end,
  lead_auditor_id FK→users, status enum (planning|active|closed), created_at
- findings: id uuid PK, audit_id FK, title varchar(200), description text, severity enum,
  department varchar(64), assignee_user_id FK→users, due_date date,
  status enum (open|in_remediation|pending_verification|closed),
  version int default 1 (optimistic lock), created_at, updated_at
- finding_comments: id uuid PK, finding_id FK, author_id FK→users, body text, created_at
- evidence_files: id uuid PK, finding_id FK, file_name, storage_path, uploaded_by FK→users,
  note text nullable, created_at
- status_history: id uuid PK, finding_id FK, from_status, to_status, actor_id FK→users,
  comment text nullable, created_at — **append only, no updates/deletes**
- Indexes: findings(status, severity, due_date), findings(assignee_user_id, status)

Workflow transitions (enforce server-side):
| From | To | Who |
| open | in_remediation | assignee (own) or auditor |
| in_remediation | pending_verification | assignee (own) — requires >=1 evidence file |
| pending_verification | closed | auditor |
| pending_verification | in_remediation | auditor (body comment required) |
| closed | — | terminal |

Business rules:
- PATCH finding uses If-Match: version header or body version; 409 on stale version.
- assignee cannot close; executive cannot POST anything.
- Overdue = due_date < today AND status not closed.
- Reports: GET /reports/overdue, /reports/by-department, /reports/by-severity.

API contracts (implement all):
| Method | Path | Auth | Behavior |
| GET | /health | none | DB ping |
| POST | /auth/login | none | JWT |

Stack: FastAPI, SQLAlchemy, local `data/evidence/`, Streamlit tabs: Finding Inbox, Audit Portfolio,
Executive Dashboard.

Seed: 2 audits, 12 findings mixed severity/status, 5 evidence files, 20+ history rows.

Tests: invalid transition 422, verification without evidence blocked, optimistic lock 409,
executive POST 403, append-only history, assignee scope, overdue report accuracy.

Out of scope: Jira, email, multi-tenant, Bedrock auto-classify.
