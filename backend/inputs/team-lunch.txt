Build a small internal Team Lunch Poll using FastAPI and Streamlit.

Problem:

Lunch choices are collected through long chat threads, and the organizer manually counts votes.
Teams need one place to create a lunch poll, vote, and view the final result.
Employees should use a simple browser page while FastAPI handles the data and business rules.

Who uses it:

Employees use Streamlit to view open polls and submit one vote.
Organizers can create polls, add restaurant options, close voting, and view results.
Streamlit must call the FastAPI API and must not access the database directly.
Health checks stay open for ops.

MVP features:

Create a lunch poll: title, lunch date, voting deadline, status.
Add restaurant options with name and optional notes.
Submit or update one vote per employee.
Show current vote counts and the winning option.
Close or cancel a poll without deleting it.
Seed one open poll and one closed poll.

Business rules:

Employees can have only one active vote per poll.
Votes cannot be submitted after the deadline or after the poll is closed.
A poll must have at least two restaurant options.
Cancelled and closed polls remain visible in history.
Only organizers can create or close polls.

Must have for v1:

Persisted data.
FastAPI backend and Streamlit frontend.
Streamlit uses FastAPI only.
Simple role distinction between employee and organizer.
Open API health endpoint.

Nice to have later:

Slack reminders, anonymous voting, dietary filters, recurring polls.

Constraints:

Internal use only.
Keep secrets out of source code.
Use Streamlit components supported by the project version.

Success:

An organizer can create a poll, employees can vote once, duplicate votes update the existing choice, voting closes at the deadline, and results remain available later.
