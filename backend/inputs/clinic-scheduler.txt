Clinic Scheduler — appointment booking for a small outpatient clinic with patients, doctors, and front-desk admins.

Client story:
A clinic books patient appointments by phone into a paper diary and keeps double-booking the same doctor. They want a system where patients request appointments, doctors see and confirm their own schedule, and front-desk admins manage everything. The system must never let a doctor be double-booked for an overlapping time, and must track each appointment through a clear lifecycle.

MVP:
- Patients request an appointment with a chosen doctor for a start/end time and reason.
- The system rejects any appointment that overlaps an existing non-cancelled appointment for the same doctor.
- Doctors view their own upcoming appointments and confirm or complete them.
- Front-desk admins view all appointments, reschedule, and cancel any appointment.
- Appointment lifecycle is an enum: requested -> confirmed -> completed, or cancelled from requested/confirmed.
- Cancellations within 2 hours of the start time are blocked for patients (admins may still cancel).

Personas & auth:
| Role | Login | Can do |
|------|-------|--------|
| patient | JWT | request own appointments; view/cancel own (outside 2h window) |
| doctor | JWT | view own appointments; confirm/complete own; cannot double-book |
| admin | JWT | view all; reschedule; cancel any; manage doctors |

Auth: JWT HS256; POST /api/v1/auth/login; Bearer on protected routes. Passwords bcrypt-hashed. Seed users with a documented shared password.

Data model (DDL under target-apps/clinic-scheduler/db/sql/):
- users: id uuid PK, username unique, password_hash, role enum(patient, doctor, admin), created_at
- doctors: id uuid PK, user_id FK -> users, full_name, specialty
- patients: id uuid PK, user_id FK -> users, full_name, date_of_birth
- appointments: id uuid PK, patient_id FK, doctor_id FK, start_time timestamptz, end_time timestamptz, status enum(requested, confirmed, completed, cancelled), reason nullable, created_at, updated_at
- appointment_events: id, appointment_id FK, from_status nullable, to_status, actor_user_id, note nullable, created_at (immutable audit of every transition)

Business rules (enforce in API, not UI only):
- Overlap prevention: reject (422) a new/rescheduled appointment whose [start,end) overlaps any existing appointment for the SAME doctor whose status is not 'cancelled'.
- end_time must be after start_time (422).
- Status transitions: only requested->confirmed (doctor/admin), confirmed->completed (doctor/admin), requested/confirmed->cancelled. Any other transition -> 409.
- A doctor can only confirm/complete their OWN appointments (403 otherwise).
- A patient can only see/cancel their OWN appointments (403 otherwise).
- Patient cancellation blocked (409) if now is within 2 hours of start_time; admin bypasses this.
- Every status change writes an appointment_events row.

API contracts (implement all):
| Method | Path | Auth | Behavior |
|--------|------|------|----------|
| GET | /health | none | DB ping |
| POST | /api/v1/auth/login | none | JWT + role |
| GET | /api/v1/me | JWT | current user profile |
| GET | /api/v1/doctors | JWT | list doctors |
| POST | /api/v1/appointments | JWT (patient) | request appointment (overlap-checked) |
| GET | /api/v1/appointments | JWT | patient: own; doctor: own; admin: all; filters status, date range |
| GET | /api/v1/appointments/{id} | JWT | 403 if out of scope |
| PATCH | /api/v1/appointments/{id}/status | JWT | transition per rules; writes event |
| PATCH | /api/v1/appointments/{id}/reschedule | JWT (admin) | change times (overlap-checked) |
| GET | /api/v1/appointments/{id}/events | JWT | transition history |

Stack:
- FastAPI + Postgres + pytest
- React/Vite under frontend/

Seed: 8 users (1 admin, 3 doctors, 4 patients) with manager-free structure, 3 doctors, 4 patients, 6 appointments spanning requested/confirmed/completed/cancelled and at least one pair that would overlap if a new booking were attempted.
Tests: overlapping booking same doctor -> 422; end before start -> 422; illegal transition (completed->requested) -> 409; doctor confirming another doctor's appt -> 403; patient cancel inside 2h window -> 409; admin cancel inside 2h -> ok.
Out of scope: billing, notifications, recurring appointments.
