Course Enrollment Hub — internal enrollment system for a training department where employees enroll in courses, get waitlisted when full, and receive grades tracked through a lifecycle.

Client story:
A corporate training team runs internal courses on a shared spreadsheet and keeps over-filling classes and losing track of who passed. They want a system where employees enroll in courses, anyone enrolling past a course's seat cap lands on a waitlist instead of being rejected, instructors record grades, and the department admin manages the whole catalog. They care most that seat limits are never silently exceeded and that a student's standing is always computed from real grade records, never hand-typed.

MVP:
- Manage a course catalog (code, title, credits, seat_capacity). Only admins create or edit courses.
- Employees enroll in a course. If seats remain, they are enrolled; if the course is at capacity, they are automatically waitlisted (not rejected).
- Enrollment status is a lifecycle enum: waitlisted -> enrolled -> completed, or dropped from waitlisted/enrolled.
- When an enrolled student drops, the earliest waitlisted student for that course is promoted to enrolled.
- Instructors record a grade for a completed enrollment. Grade changes are recorded to an immutable audit trail.
- A student's GPA is always computed from their completed enrollments' grades and course credits; it is never stored.
- Admin-only screen: an administration area to manage the catalog and view every student's full enrollment record across all courses.

Personas & auth:
| Role | Login | Can do |
|------|-------|--------|
| student | JWT | enroll in / drop own courses; view own enrollments and computed GPA |
| instructor | JWT | view own courses' rosters; record and change grades |
| admin | JWT | manage the course catalog; view all students' enrollments; assign roles |

Auth: JWT HS256; POST /api/v1/auth/login; Bearer on protected routes. Passwords bcrypt-hashed. Seed users with a documented shared password.

Data model (DDL under target-apps/course-enrollment-hub/db/sql/):
- users: id uuid PK, username unique, password_hash, role enum(student, instructor, admin), full_name, created_at
- courses: id uuid PK, code unique, title, credits int NOT NULL, seat_capacity int NOT NULL, instructor_user_id FK -> users nullable, created_at
- enrollments: id uuid PK, course_id FK, student_user_id FK, status enum(waitlisted, enrolled, completed, dropped), grade_points numeric(3,2) nullable, enrolled_at timestamptz, updated_at, composite uniqueness on (course_id, student_user_id)
- grade_events: id, enrollment_id FK, from_grade numeric(3,2) nullable, to_grade numeric(3,2), actor_user_id FK, note nullable, created_at (immutable audit of every grade set/change)

Business rules (enforce in API, not UI only):
- Capacity: on enroll, if current enrolled count for the course < seat_capacity, set status enrolled; otherwise set status waitlisted. Never exceed seat_capacity with status enrolled.
- Promotion: when an enrolled student moves to dropped, promote the earliest-enrolled_at waitlisted student for that course to enrolled (if any).
- A student cannot enroll in the same course twice (409 on duplicate active enrollment).
- Status transitions: waitlisted->enrolled (system/admin), enrolled->completed (instructor/admin), waitlisted/enrolled->dropped. Any other transition -> 409.
- Only an instructor of that course, or an admin, may record/change a grade (403 otherwise). A grade may only be set on a completed enrollment (409 otherwise).
- grade_points must be between 0.00 and 4.00 (422 otherwise).
- Every grade set or change writes a grade_events row.
- GPA = sum(grade_points * course.credits) / sum(course.credits) over the student's completed enrollments; computed on read, never stored.

API contracts (implement all):
| Method | Path | Auth | Behavior |
|--------|------|------|----------|
| GET | /health | none | DB ping |
| POST | /api/v1/auth/login | none | JWT + role |
| GET | /api/v1/me | JWT | current user profile |
| GET | /api/v1/courses | JWT | list courses with enrolled/waitlist counts |
| POST | /api/v1/courses | JWT (admin) | create course |
| PUT | /api/v1/courses/{id} | JWT (admin) | edit course |
| POST | /api/v1/courses/{id}/enroll | JWT (student) | enroll self; auto-waitlist if full |
| GET | /api/v1/enrollments | JWT | student: own; instructor: own courses' rosters; admin: all |
| PATCH | /api/v1/enrollments/{id}/status | JWT | transition per rules; triggers promotion on drop |
| PATCH | /api/v1/enrollments/{id}/grade | JWT (instructor/admin) | set/change grade; writes grade_event |
| GET | /api/v1/students/{id}/gpa | JWT | computed GPA for a student |
| GET | /api/v1/admin/students | JWT (admin) | admin-only: every student with full enrollment record |

Stack:
- FastAPI + Postgres + pytest
- React/Vite under frontend/

Seed: 8 users (1 admin, 2 instructors, 5 students) with a documented shared password, 4 courses (at least one with seat_capacity small enough that seeded enrollments fill it and push one student to waitlisted), enrollments spanning waitlisted/enrolled/completed/dropped, and grades on the completed ones so a computed GPA is non-trivial.
Tests: enroll into a full course -> waitlisted not rejected; drop an enrolled student -> earliest waitlisted promoted to enrolled; enroll same course twice -> 409; grade outside 0..4 -> 422; student recording a grade -> 403; instructor grading own course -> ok; illegal transition (completed->waitlisted) -> 409; GPA reflects completed grades weighted by credits; admin students endpoint returns all students, non-admin -> 403.
Out of scope: prerequisites, semesters/terms, transcripts export.
