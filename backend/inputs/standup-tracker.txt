Sprint Standup Tracker for engineering teams.

Problem:
- Daily standup notes get lost in Slack threads or forgotten by Friday.
- Managers want a short weekly view of what the team did, what is planned, and what is blocked — without digging through chat history.

Who uses it:
- Team members submit daily standup notes (what they did, what they plan, any blockers).
- Managers generate and read weekly summaries for a chosen date range.
- v1 uses a shared API key from the app (no personal login table yet). Health checks stay open for ops.

MVP features:
- Submit a standup entry: team member name, date, yesterday, today, optional blockers.
- Browse standup history with filters by person and date range.
- Generate a weekly AI summary from the standups in that week (grouped by person, with team summary, blockers, and key achievements).
- List past weekly summaries.
- A simple Streamlit UI with tabs to submit standups, view history, and generate/view weekly summaries.
- Seed a few sample standups for the current week and one prior weekly summary so demos work immediately.

Business rules:
- Summaries must only use real standup entries in the selected date range — never invent updates.
- If there are no standups in range, say clearly that there is no data and how to add some.
- Requests without a valid API key should be rejected (except health).

Must have for v1:
- Persisted data (not in-memory only).
- Backend API plus Streamlit UI that talks to the API over HTTP.
- AI summary generation that can be demoed (mockable in tests).

Nice to have (later):
- Slack bot, calendar sync, team admin CRUD, personal logins / SSO, Confluence posting.

Constraints:
- Internal use only; manual entry in v1 (no Slack/Jira integration yet).
- Keep secrets out of source code and out of generated summaries.

Success:
- A teammate submits standups in the UI; a manager picks a week, generates a Markdown summary, and can reopen past summaries.
- Filtering history by person or dates shows the right entries.
