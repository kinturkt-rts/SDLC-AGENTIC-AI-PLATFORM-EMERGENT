App idea (one paragraph):
Internal teams post short **notices** (announcements, reminders, wins) on a shared board.
Anyone can read active notices via the API; organizers with a shared API key create, update,
or archive notices. No login UI, no LLM, no Streamlit — FastAPI + Postgres + Swagger at /docs.
Small enough for a reliable agent chain test; rich enough to produce real SQL, routes, and tests
for GitLab publish verification.

Purpose:
- End-to-end chain: **product-agent → architect-agent → database-agent → developer-agent**
  then **gitlab-agent** branch publish.
- Developer pattern: **B** (Postgres CRUD + API-key auth) — no JWT, Bedrock, pgvector, or UI folder.
- Validates PRD/design/SQL/app artifacts land on `sdlc/gitlab-pipeline-smoke` in GitLab monorepo.

Current pain:
- Team updates live in Slack and get buried.
- No simple read API for dashboards or bots to surface “what’s active this week”.

MVP:
- Notice categories (e.g. General, HR, Engineering) with name + optional description.
- Notices: title, body (markdown plain text), category, author display name, publish window
  (starts_at, ends_at optional), active flag.
- Public read: list/filter active notices; get by id.
- Organizer writes: create/update/archive notices and manage categories (API key).
- Auto-hide notices past ends_at in list endpoints (filter in query, do not delete rows).

Personas & auth:
| Caller | Auth | Can do |
|--------|------|--------|
| anonymous | none | GET /health, GET /categories, GET /notices (list + by id) |
| organizer | `X-API-Key: <API_KEY>` | POST/PATCH categories; POST/PATCH /notices; POST /notices/{id}/archive |

Auth implementation (MVP — API key only):
- Load `API_KEY` from env via pydantic-settings (`.env.example`: `API_KEY=dev-api-key-change-me`).
- Dependency `verify_api_key` on write routes; missing/wrong key → 401.
- **No JWT**, **no users table**, **no bcrypt**, **no sessions**.

Data model (database-agent owns `target-apps/gitlab-pipeline-smoke/db/sql/`):
- categories:
  - id uuid PK
  - name text NOT NULL UNIQUE (1–60 chars)
  - description text nullable (max 240)
  - created_at timestamptz NOT NULL DEFAULT now()
- notices:
  - id uuid PK
  - category_id uuid FK→categories ON DELETE RESTRICT
  - title text NOT NULL (1–120)
  - body text NOT NULL (1–4000)
  - author_name text NOT NULL (1–80)
  - starts_at timestamptz nullable (default now() on create if omitted)
  - ends_at timestamptz nullable
  - is_archived bool NOT NULL DEFAULT false
  - created_at timestamptz NOT NULL DEFAULT now()
  - updated_at timestamptz NOT NULL DEFAULT now()
- Index on (is_archived, starts_at DESC) for list queries.

Seed data (database-agent dev seed — stable UUIDs, ON CONFLICT DO NOTHING):
- 3 categories: General, HR, Engineering
- 5 notices: mix of active, future starts_at, expired ends_at, and one archived
- Use realistic author_name values (e.g. "Jordan Lee", "Sam Patel")

API contracts:
| Method | Path | Auth | Behavior |
| GET | /health | none | `{"status":"ok","service":"gitlab-pipeline-smoke"}` |
| POST | /categories | API key | create; 201; 409 duplicate name |
| GET | /categories | none | list all sorted by name |
| GET | /categories/{id} | none | 200 or 404 |
| PATCH | /categories/{id} | API key | update name/description; 409 name clash |
| POST | /notices | API key | create; 404 unknown category; 422 if ends_at < starts_at |
| GET | /notices | none | paginated list; query `?category_id=` `?active_only=true` (default true) `?q=` search title/body `?limit=` `?offset=` |
| GET | /notices/{id} | none | 200 or 404 |
| PATCH | /notices/{id} | API key | update fields; bump updated_at; same validation as create |
| POST | /notices/{id}/archive | API key | set is_archived=true; 204; idempotent if already archived |

Business rules:
- `active_only=true` (default): exclude archived; exclude where ends_at < now(); exclude where starts_at > now().
- List shape: `{items, total, limit, offset}`.
- `q` search: case-insensitive partial match on title OR body.
- PATCH/POST without API key → 401.
- Cannot create notice for unknown category_id → 404.

Stack (developer-agent — Pattern B):
- Python 3.12, FastAPI, Pydantic v2, pydantic-settings, uvicorn.
- SQLAlchemy 2.x sync + psycopg[binary]; `postgresql+psycopg://` in `.env.example` with `?sslmode=require`.
- POSTGRES_SCHEMA=gitlab_pipeline_smoke; dialect-guarded `database.py` (Postgres + SQLite for pytest).
- Layout: `app/routers/health.py`, `categories.py`, `notices.py`;
  `app/models/`, `app/schemas/`, `app/dependencies.py`, `app/config.py`, `app/main.py`.
- `.env.example`: DATABASE_URL, POSTGRES_SCHEMA=gitlab_pipeline_smoke, API_KEY, PORT=8000
- **No boto3, no Bedrock, no pgvector, no Streamlit, no JWT libraries.**

Tests (developer baseline):
- pytest + TestClient; SQLite in-memory for unit tests.
- Cover: health, list pagination shape, create category+notice with API key,
  write without key → 401, active_only filters expired/future/archived,
  archive endpoint, search `?q=`, duplicate category → 409, ends before starts → 422.
- README curl examples with `X-API-Key` on write routes.
